## Что защищено и как

### Аутентификация и сессии
- Пароль хэшируется `scrypt` (N = 2¹⁵) со случайной солью; параметры записаны в хэш.
- Для несуществующего e-mail хэш всё равно вычисляется — время ответа не выдаёт, зарегистрирован ли адрес.
- Токен сессии — 32 случайных байта; в базе только его SHA-256. Cookie `HttpOnly`, `SameSite=Lax`, `Secure` в продакшене.
- Выход удаляет сессию на сервере. Блокировка аккаунта удаляет все его сессии.
- Ограничение частоты: вход — 10 попыток на e-mail за 15 минут и 20 на IP за 5 минут; регистрация — 10 в час с IP.

### Права доступа
- Сессия проверяется в каждом обработчике (`requireUser`); `proxy.ts` делает только удобный редирект.
- Чат, платёж и фото ищутся с условием «принадлежит мне». Чужой объект — это 404, а не 403: существование не раскрывается.
- Раздел модерации требует роль `admin` на сервере; интерфейс лишь прячет ссылку.

### Подделка запросов и ввод
- CSRF: `SameSite=Lax` и проверка заголовка `Origin` у всех изменяющих запросов.
- Все входные данные проходят схемы Zod; запросы к базе параметризованы через Drizzle.
- Пользовательский текст выводится средствами React и экранируется; `dangerouslySetInnerHTML` не используется.
- Спецсимволы `LIKE` в поиске экранируются. Идентификаторы в адресе проверяются по формату UUID.
- После входа возврат возможен только на внутренний адрес (защита от open redirect).

### Приватность
- В ответах API нет координат, e-mail и даты рождения других людей — только возраст и округлённое расстояние.
- Всё, что ближе километра, показывается как «1 км»; координаты хранятся с точностью около километра.
- Без подписки сервер отдаёт в «Лайках» только размытые превью 24 px — настоящие фото и id в ответ не попадают.

### Загрузка файлов
- Формат определяется по содержимому, а не по расширению. Файл пересохраняется в WebP — исходные байты не раздаются.
- Метаданные (геометка, модель устройства) удаляются. Есть лимиты на размер файла, число пикселей и количество фото.
- Имя файла — случайный UUID. Раздача проверяет, что путь не выходит из папки загрузок.

### Платежи
- Клиент присылает только id тарифа; сумма берётся из каталога на сервере.
- Доступ выдаётся условным `UPDATE … WHERE status = 'pending'`: повторный вебхук или двойной клик не продлят срок дважды.
- Телу вебхука ЮKassa не доверяем: берём id платежа и перепроверяем статус и сумму через её API.

### Заголовки
`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`.

## Зависимости

`npm audit --omit=dev` — **0 уязвимостей** в том, что попадает в продакшен.

`npm audit` целиком — 11 замечаний (6 средних, 5 высоких), все в инструментах разработки: старый `esbuild` внутри
`drizzle-kit`, `braces` в цепочке ESLint, `@dicebear/initials` в генераторе демо-портретов. В собранное приложение
эти пакеты не входят.

## Известные ограничения

| Ограничение | Почему важно | Что сделать |
| --- | --- | --- |
| Нет подтверждения e-mail и восстановления пароля | Можно зарегистрироваться на чужой адрес; забытый пароль не вернуть | Подключить почтовый сервис, добавить одноразовые ссылки |
| Нет Content-Security-Policy | Нет второго рубежа против XSS | CSP с nonce по руководству Next.js |
| Демо-режим и тестовая касса | С `PAYMENT_PROVIDER=demo` подписка выдаётся без оплаты | В боевом окружении — `yookassa` и без `DEMO_MODE` |
| Фото не модерируются | Возможны чужие или недопустимые изображения | Очередь модерации или автоматическая проверка |
| IP берётся из `X-Forwarded-For` | За собственным прокси заголовок можно подделать | Настроить доверенный прокси |
| ЮKassa, Google OAuth и push не запускались с настоящими ключами | Код написан по документации, но не проверен в работе | Проверить на тестовых ключах |
| Ссылки на фото публичны | Зная адрес, файл можно открыть без входа | Подписанные ссылки с коротким сроком |
